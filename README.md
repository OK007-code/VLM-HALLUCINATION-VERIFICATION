# Evidence-Based Hallucination Detection in Multimodal LLMs

> **Verifiability-Aware Hallucination Detection with Decision-Consequence Severity Scoring for Vision-Language Models**

An evidence-based framework for detecting, verifying, and analyzing hallucinated claims generated by Vision-Language Models (VLMs) using independent visual and textual evidence.

## 📖 About the Project

Vision-Language Models (VLMs) can generate fluent and convincing descriptions of images, but they may sometimes produce information that is not actually supported by the visual content.

For example, a VLM may answer:

> "There is a cat sitting next to the dog."

when the image contains a dog but no cat.

This project develops an evidence-based framework that does not blindly trust the VLM's response. Instead, the generated response is broken into individual claims and each claim is independently verified using visual and textual evidence.

### Core Principle

> A VLM-generated claim should be verified using independent evidence before it is considered reliable.

---

## 🎯 Problem Statement

VLM hallucinations are difficult to detect because:

- VLM responses can sound highly confident.
- A single computer-vision detector can miss objects.
- Blurry, occluded, or ambiguous images can cause detection failures.
- Detector disagreement does not necessarily mean that the VLM hallucinated.
- Not every incorrect claim has the same practical consequence.

Therefore, the system distinguishes between:

```text
SUPPORTED
    ↓
Sufficient independent evidence exists

AMBIGUOUS
    ↓
Evidence is weak, conflicting, or insufficient

UNVERIFIED
    ↓
The claim cannot currently be established

The system avoids automatically treating the absence of detection as proof of hallucination.

🧠 System Workflow
1. VLM Response Generation

An image and a question are provided to a Vision-Language Model.

The current prototype uses:

BLIP VQA

Model: Salesforce/blip-vqa-base

Example:

Question:
"Is there a dog?"

VLM Answer:
"Yes."
2. Claim Extraction

The generated VLM response is converted into individual claims.

Example:

VLM Response:
"There is a dog and four people. The car is red."

becomes:

Claim 1 → There is a dog.
Claim 2 → There are four people.
Claim 3 → The car is red.
3. Claim Normalization

Claims are normalized into a consistent format so that they can be processed automatically by the verification pipeline.

Example:

"There is a dog."
        ↓
Object = dog
Claim Type = Object
🏷️ Claim Types

The system currently considers the following claim categories:

Claim Type	Example	Verification
Object	"There is a dog."	YOLO + Grounding DINO
Count	"There are 4 people."	Object counting
Attribute	"The car is red."	Visual attribute analysis
Spatial	"The dog is to the right of the car."	Bounding-box analysis
Text	"The sign says OPEN."	OCR
🔎 Evidence Extraction
YOLO

YOLO is used as an independent object detector.

It provides:

Object class
Confidence score
Bounding box
Object count

Example:

dog       → 0.919
car       → 0.809
person    → 0.887
Grounding DINO

Grounding DINO provides text-guided and open-vocabulary visual detection.

For example:

Claim:
"There is a dog."

Query:
"a dog."

        ↓

Grounding DINO
        ↓
Object location + confidence

Using two independent detection sources allows the system to compare their evidence.

📐 YOLO–Grounding DINO IoU Matching

The system compares YOLO and Grounding DINO bounding boxes using Intersection over Union (IoU).

IoU
IoU = Intersection Area / Union Area

Conceptually:

YOLO Box
┌───────────────┐
│      DOG      │
│               │
└───────────────┘
       ∩
DINO Box
┌───────────────┐
│      DOG      │
└───────────────┘

        ↓

Spatial Agreement

A sufficient overlap between the two detections provides stronger cross-source evidence.

🛡️ Verifiability Gate

The Verifiability Gate is the central decision layer of the system.

It combines evidence from the available verification modules.

Strong Evidence
Claim:
"There is a dog."

YOLO            → FOUND
Grounding DINO  → FOUND
IoU              → Sufficient

        ↓

Gate   → VERIFIABLE
Status → SUPPORTED
Detector Disagreement
Claim:
"There is a cat."

YOLO            → NOT FOUND
Grounding DINO  → FOUND

        ↓

Gate   → AMBIGUOUS
Status → UNVERIFIED

The system does not automatically classify detector disagreement as hallucination.

This is important because detection can fail due to:

Occlusion
Blur
Small objects
Poor image quality
Detector limitations
🔤 OCR Evidence

For claims involving text, the system uses EasyOCR.

Image
  ↓
EasyOCR
  ↓
Detected Text
  ↓
Confidence
  ↓
Claim Verification

Example:

Claim:
"The sign says OPEN."

OCR:
"OPEN"

Confidence: 0.94

→ Text claim supported

If OCR cannot find readable text, the claim is treated as unverified/ambiguous rather than automatically hallucinated.

🔄 Unified Claim Verification

A central verify_claim() function routes each claim to the appropriate verification module.

                    verify_claim()
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
      Object            Count             Text
        │                 │                 │
        ▼                 ▼                 ▼
 YOLO + DINO          Counting            OCR
      + IoU            Evidence          Evidence
        │                 │                 │
        └─────────────────┼─────────────────┘
                          ▼
                   Verification Result

Spatial and attribute claims are handled using their respective visual verification logic.

📊 Response-Level Verification

After individual claims are verified, their results are aggregated to evaluate the entire VLM response.

Example:

============================================================
             RESPONSE-LEVEL VERIFICATION
============================================================

Total Claims       : 4
Supported          : 2
Ambiguous          : 1
Unverified         : 1

Evidence Coverage  : 50%

Response Status    : PARTIALLY VERIFIED
============================================================

This provides a higher-level assessment of whether the complete VLM response is supported by available evidence.

⚖️ Decision-Consequence Severity (DCS)

The next major component is Decision-Consequence Severity (DCS).

Not every hallucinated claim has the same impact.

For example:

Incorrect claim:
"The dog is slightly to the right."

vs.

Incorrect claim:
"There is a person holding a weapon."

The consequences of these claims can be significantly different.

The proposed DCS approach therefore examines whether correcting or removing an incorrect claim changes the final answer or decision.

Answer-Flip Testing
Original VLM Response
        ↓
Claim Verification
        ↓
Identify Incorrect Claim
        ↓
Correct / Remove Claim
        ↓
Compare Responses
        ↓
Answer Flip?
        ↓
Decision-Consequence Severity

VLM Claims

YOLO

Grounding DINO
